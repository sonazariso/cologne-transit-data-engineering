## 2. Audit existing SQL Server backups before creating another one

First inspect SQL Server backup history in `msdb`.

For `CologneTransitIntelligence`, report all relevant recent FULL backups, including:

- backup start time;
- backup finish time;
- backup type;
- backup file/device path;
- database name;
- backup size;
- compressed backup size where available;
- whether checksum information is available;
- recovery model;
- first/last/database backup LSN information where available.

Also inspect the actual backup location/file if accessible.

Do not claim that an existing backup is valid merely from `msdb` history.

For the newest credible FULL backup, perform safe verification using:

`RESTORE VERIFYONLY`

with checksum verification where supported by that backup.

Do not restore over the production database.

If an existing FULL backup is:

- recent enough to represent the current project database state;
- physically accessible;
- successfully validated;
- and clearly attributable to `CologneTransitIntelligence`;

then reuse it as the Stage 1 safety backup and do not create an unnecessary duplicate.

If no such verified backup exists, create a new native SQL Server FULL backup using:

- `COPY_ONLY`;
- `COMPRESSION`;
- `CHECKSUM`;
- a timestamped filename;
- no overwrite of an existing historical backup.

Then run:

`RESTORE VERIFYONLY`

against the newly created backup.

Generate SHA-256 for the final `.bak` file if practical in the current VM environment.

Do not delete older backups.
