## 2. Fix scheduled-time timezone semantics

Current `schedule_time_seconds()` takes the lexical clock portion of an ISO timestamp.

That is not sufficient for real MDD values such as:

`2026-09-26T09:29:00Z[GMT]`

because MDD supplies an absolute UTC timestamp while GTFS scheduled times are service-day schedule offsets.

Do not compare UTC clock time directly with GTFS local schedule seconds.

Implement an explicit alignment contract:

MDD/TRIAS absolute timetabled timestamp
→ validated local feed timezone / Europe-Berlin semantics
→ GTFS service date + service-day seconds

Requirements:

- preserve the original source timestamp;
- use timezone-aware conversion when the source contains an explicit timezone;
- handle DST correctly;
- retain GTFS times above 24:00 without modulo wrapping;
- do not fabricate a timezone for timezone-less source values;
- treat timezone-unresolved values as insufficient for an absolute-time match;
- keep `OperatingDayRef` available independently.

Add boundary tests for normal CET/CEST cases, midnight crossings, and GTFS extended-hour values.

Do not derive service date from `ObservedAt`.
