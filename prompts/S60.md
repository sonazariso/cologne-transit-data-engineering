## Problem

The Stage 11 documentation currently says in several places that:

`Dim Sampling Era` may filter matching/Data Quality evidence where validated lineage exists.

However, the complete approved base relationship matrix currently contains only:

`Dim Sampling Era[SamplingEraKey] -> Fact Matching Decision[SamplingEraKey]`

There is no approved relationship from `Dim Sampling Era` to:

`Fact Data Quality Issue`

and no validated `SamplingEraKey` lineage for that independent semantic fact has been established.

Because the relationship matrix is authoritative and complete, the current wording is too broad and could cause a future Power BI implementation to invent an unsupported relationship.

- `Data Quality Issue Count` must not be described or implemented as Sampling-Era-filterable under the current base model.
- Do not add a relationship from `Dim Sampling Era` to `Fact Data Quality Issue` unless a future stage establishes and validates explicit SamplingEra lineage at that fact's grain.

`Dim Sampling Era currently filters the Fact Matching Decision population. Data Quality classifications carried by those matching decisions inherit that context. The separate Fact Data Quality Issue is not Sampling-Era-filtered in the base model unless future validated lineage explicitly supports it.`
