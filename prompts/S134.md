## Correct the Windows evidence UTC timestamp handling

Inspect:

`scripts/capture_windows_sql_admin_evidence.ps1`

The SQL identity query retrieves the capture timestamp using:

`SYSUTCDATETIME()`

However, the Windows script subsequently parses that value and calls `ToUniversalTime()`.

A SQL datetime2 value does not intrinsically carry timezone information.

If the SQL driver produces a DateTime with unspecified timezone information, PowerShell may interpret it as Windows local time before converting it to UTC.

This can introduce a timezone offset into an already-UTC timestamp.

Correct the conversion so a timestamp obtained from SYSUTCDATETIME is explicitly treated as UTC.

Do not reinterpret it as local time.

Use one consistent, unambiguous ISO-8601 UTC representation throughout:

- Initial Windows capture.
- Intermediate signed Windows evidence.
- Final merged Mac evidence.
- SQL instance provenance.
- Resume freshness validation.

Add regressions for:

- UTC Windows timezone.
- Europe/Berlin standard time.
- Europe/Berlin daylight-saving time.
- DateTime values with unspecified Kind.
- Explicit UTC values.
- Windows PowerShell 5.1.
- PowerShell 7.
- Capture immediately before a DST transition.
- A genuinely stale artifact.
- A future-dated artifact.

Prove that an actual fresh SQL UTC timestamp survives the Windows-to-Mac conversion without a one- or two-hour offset.

Do not increase the 30-minute freshness limit to hide the defect.
