## 1. Complete the quota-permit lifecycle

Atomic quota reservation now works, but the permit lifecycle is incomplete for future live execution.

The current execution releases a quota permit immediately after the transport call and only afterward records the attempt.

This creates an unsafe accounting gap for future live concurrency.

Replace the simple reserve/release model with a durable permit lifecycle that distinguishes at minimum:

- pending authorization;
- released because no network request occurred;
- conservatively consumed live attempt;
- confirmed provider HTTP attempt.

Equivalent names are acceptable, but the semantics must be explicit.

A live permit must never become available for reuse between the moment a network request is attempted and the moment the attempt is durably accounted.

## 2. Preserve Stage 13 accounting distinctions

The collector must preserve the established accounting concepts:

- client-side live invocation;
- HTTP response received;
- confirmed provider HTTP attempt;
- provider quota consumption unknown when transport fails before an HTTP response;
- conservative quota accounting attempt.

Do not collapse these into one count.

For safe runtime quota protection:

- a live client invocation that actually reaches the transport attempt boundary must count conservatively against collector-managed quota headroom;
- an HTTP response confirms the provider HTTP attempt;
- a transport failure after a real network attempt may remain provider-quota-unknown but must not immediately return its quota headroom for reuse;
- credential/request-contract failures before network activity must not consume provider quota or conservative live-attempt headroom.

## 3. Correct the dead provider-attempt-confirmation field

The SQLite `http_attempts` model currently contains `provider_attempt_confirmed`, but runtime attempt recording always writes zero.

Implement the intended semantics.

For an HTTP response received from the MDD request path:

- `http_response_received = true` or equivalent;
- provider HTTP attempt confirmed = true.

For a transport failure with no HTTP response:

- provider HTTP attempt confirmed = false;
- provider quota status remains unknown;
- conservative live-attempt accounting remains active if a real network attempt occurred.

For simulated/offline calls:

- provider HTTP attempt confirmed = false;
- conservative provider quota accounting = false.

Do not count fake or fixture calls as provider usage.

## 4. Add explicit transport-attempt metadata

Extend the transport result contract so the collector can distinguish at minimum:

HTTP responses must indicate:

## 5. Make quota permit finalization atomic

Add persistence/usage-port operations equivalent to:

- reserve permit;
- finalize permit as no-network/released;
- finalize permit as conservative live consumption;
- finalize/confirm HTTP provider attempt.

The finalization that converts a pending permit into consumed accounting must be transactional.

There must be no observable state in which:

- the permit is released;
- the live attempt has happened;
- but the usage/accounting record has not yet been updated.

Design this contract so the future PostgreSQL adapter can implement it atomically.
