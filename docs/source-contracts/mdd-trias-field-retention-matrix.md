# MDD/TRIAS Field-Retention Matrix

**Stage:** 02 — MDD/TRIAS Source-Contract Audit<br>
**Document state:** Approval candidate; not user-approved<br>
**Semantic authority:** VDV 431-2, “EKAP-Schnittstellenbeschreibung V1.2”, 02/2017<br>
**Controlled response:** Köln Hbf, arrival, five results, one point in time

This matrix is a source-contract and retention decision. It is not a SQL
schema. It deliberately preserves the distinction between:

1. what TRIAS 1.2 defines or permits;
2. what appeared in the one controlled MDD response;
3. what the Legacy parser handled; and
4. what the Legacy persistence path mapped from the parsed snapshot.

For a candidate field absent from the controlled response, the observation
status is `SPEC_DEFINED_NOT_OBSERVED` where the semantic field is known. This
does not mean unsupported, unavailable from MDD generally, or safe to discard.
`NOT_ESTABLISHED_IN_SUPPLIED_SEMANTICS` is used only where the supplied
evidence does not establish a precise normative role.

## Retention principles

The matrix applies these principles to all rows:

- preserve nullable source semantics;
- preserve identities needed for matching;
- preserve fields needed to distinguish scheduled, estimated, and actual
  timing;
- preserve operational flags as independent fields;
- preserve situation association scope;
- preserve arrival/departure context;
- preserve Previous/This/Onward call scope where collected; and
- do not persist only a derived delay while discarding its source timestamps.

Stage 02 does not design SQL columns or tables. The Legacy persistence column
names above are evidence of the existing implementation only.
